Del pedido al comando

No usamos la terminal: entendemos la intención y OpenClaw ejecuta

VER

«¿Qué cambió?»

Revela el alcance antes de actuar.

ELEGIR

«Incluye solo estos»

git add archivo...

Define qué entra al próximo commit.

REVISAR

«Muéstrame la propuesta»

git diff --cached

Permite detectar errores o secretos.

Intención → pedido → evidencia08 / 36

Staging

La zona staged es una propuesta revisable, no una sala de espera automática

Pídeselo así

«Prepara solo README.md y RECOVERY-DEMO.md; no incluyas nada más».

git add README.md RECOVERY-DEMO.md

Luego revisa

«Enséñame nombres, diff y búsqueda sensible; detente».

git diff --cached --name-status
git diff --cached

Durante la clase no usamos git add . como reflejo: primero nombramos qué entra.

El staging define el perímetro09 / 36

Commit

Un buen commit registra una decisión coherente que otro lector puede entender

Pídeselo así

«Propón un mensaje claro, muéstrame el resumen y espera mi aprobación».

git commit -m "chore: versiona snapshot sanitizado"

Después, publicar

«Publica el commit aprobado en origin y devuélveme URL, rama y hash».

git push

push copia la historia local al remoto.

Semáforo de archivos

La decisión de versionar depende del contenido, no de que el archivo termine en .md

VERDE · incluir

IDENTITY, SOUL, AGENTS, TOOLS, HEARTBEAT, BOOTSTRAP y README sanitizados.

AMARILLO · revisar

USER, MEMORY, estados de proyecto, rutas personales y capturas.

ROJO · excluir

openclaw.json, .env, credenciales, pairing, llaves, logs y SQLite.

Trampa frecuente

Ignorar un archivo tarde no lo saca del historial que Git ya conoce

archivo rastreado+regla nueva≠archivo olvidado

Antes del primer commit

Crea `.gitignore`, luego selecciona archivos.

Si ya fue rastreado

Detente y consulta; no improvises una reescritura de historial en clase.

Snapshot deliberado

Una carpeta normal puede convertirse después en un repo Git, sin versionar todo el agente

mi-agente-infra/
├── .gitignore
├── README.md
├── RECOVERY-DEMO.md
└── workspace/
    ├── IDENTITY.md
    ├── SOUL.md
    ├── AGENTS.md
    ├── TOOLS.md
    ├── HEARTBEAT.md
    └── BOOTSTRAP.md

No es un backup ciego

Es una selección entendible y auditable de lo necesario para reconstruir comportamiento.

La memoria requiere otra decisión

`USER.md` y `MEMORY.md` solo entran después de sanitizar datos personales y confirmar su utilidad.

Puedes crear el agente primero y ejecutar después git init en una carpeta nueva. Git versiona solo lo que seleccionemos; no es necesario subir todo el estado vivo.

Primer commit

El flujo local queda cerrado antes de pedirle a GitHub que publique algo

El orden importa: inicializar → seleccionar → revisar → registrar → comprobar.

Recuperación local

Restaurar un archivo de prueba demuestra el valor del commit sin arriesgar el workspace

git diff -- RECOVERY-DEMO.md
git restore -- RECOVERY-DEMO.md
git status --short

Antes

El diff muestra la modificación deliberada.

Después

El archivo vuelve a `HEAD` y el resto del proyecto queda intacto.

La práctica usa un archivo descartable: no se aprende recuperación destruyendo trabajo real.

Recuperación remota

★

Clonar en otra carpeta prueba que el proyecto ya no depende de la original

cd ..
gh repo clone TU_USUARIO/mi-agente-infra recuperacion-mi-agente
git -C recuperacion-mi-agente rev-parse --short HEAD
git -C mi-agente-infra rev-parse --short HEAD

Si los hashes coinciden y los archivos abren, el remoto puede reconstruir el snapshot.
