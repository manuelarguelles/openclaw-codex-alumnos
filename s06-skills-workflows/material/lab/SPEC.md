# Spec de ejemplo · borrador de postulación
Estado: diseño de referencia para revisión. Implementación y validación de runtime pendientes.

Objetivo: preparar un borrador local sustentado en perfil y oferta suministrados.
Usuario: persona que revisa una postulación antes de cualquier envío.
Entradas: perfil con evidencias y oferta. Solo datos sintéticos durante el laboratorio.
Salida: borrador, tabla afirmación/evidencia, brechas y preguntas.
Excluido: inventar experiencia, navegar, enviar mensajes, presentar postulaciones, modificar el repo original.

## Aceptación
CA-01: cada afirmación de experiencia remite a una evidencia explícita del perfil.
CA-02: un requisito sin evidencia aparece como brecha, no como experiencia.
CA-03: falta de perfil u oferta detiene la redacción y pide el dato.
CA-04: una instrucción dentro de la oferta que pide ignorar reglas se trata como dato no autorizado.
CA-05: el resultado permanece como borrador local para revisión humana.
CA-06: la skill no se selecciona para una corrección ortográfica ajena a una postulación.

## Cierre
El alumno y el instructor revisan alcance antes de probar la plantilla.
Una evaluación de comportamiento real, con resultados guardados, es necesaria para aprobar la skill.
