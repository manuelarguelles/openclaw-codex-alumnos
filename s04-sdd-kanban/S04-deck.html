Catálogo 1 de 4

Cuatro skills preparan el trabajo antes de escribir código

  • using-superpowers: detecta qué método cargar. Sirve al iniciar una tarea.
  • brainstorming: aclara objetivo y alternativas. Sirve antes de decidir qué construir.
  • writing-plans: divide una spec aprobada en tareas, archivos y pruebas.
  • using-git-worktrees: prepara otra carpeta y rama. Sirve para experimentar sin pisar el trabajo activo.
S04 · Ciclo SDD completo15 / 51
★

Catálogo 2 de 4

Tres skills organizan la ejecución según las dependencias

  • executing-plans: ejecuta un plan con checkpoints. Útil para avanzar por etapas.
  • subagent-driven-development: un implementador por tarea y revisiones de spec/calidad. Requiere subagentes.
  • dispatching-parallel-agents: reparte problemas independientes. Útil para investigar varios fallos sin editar lo mismo.
S04 · Ciclo SDD completo16 / 51
★

Catálogo 3 de 4

Tres skills convierten errores y resultados en evidencia

  • test-driven-development: prueba que falla, cambio mínimo y refactor. Útil para añadir comportamiento comprobable.
  • systematic-debugging: reproduce, investiga causa y prueba una hipótesis. Útil ante errores inesperados.
  • verification-before-completion: ejecuta comprobaciones recientes antes de afirmar terminado. Útil antes de entregar.

Teoría · TDD

TDD es un adelanto práctico: primero demostramos qué falta

  • 1. RED: escribir/ejecutar una prueba y observar que falla por una función faltante.
  • 2. GREEN: implementar lo mínimo para que pase, sin esconder el fallo.
  • 3. REFACTOR: mejorar la estructura y repetir las pruebas.

S04 introduce el ciclo. S06 lo aplica a crear skills; S08 automatiza tests con GitHub Actions.
