El problema de «arreglar esto»

«Arreglar esto» no alcanza porque no dice qué logra, hasta dónde ni cómo se comprueba

Idea suelta

  • «Mejora mi agente»
  • «Que responda mejor»
  • «Arregla lo de ayer»

Lo que le falta

  • Un objetivo en una oración
  • Un límite de qué sí y qué no
  • Una forma observable de comprobarlo
Nombrar el hueco antes de llenarlo06 / 31

Especificación breve

Tres partes mínimas bastan para que otra persona ejecute tu idea sin preguntarte nada

OBJETIVO

Una oración

Qué resuelve, dicho una sola vez.

ALCANCE

Qué sí, qué no

Evita que un cambio pequeño se vuelva infinito.

CRITERIO

Cómo se comprueba

Una condición observable, no una sensación.

Sin estas tres partes, es una intención07 / 31

Pasos pequeños

Un paso cabe en pocos minutos y termina en algo comprobable, no en «sigue trabajando»

paso pequeño→chequeo contra el criterio→evidencia→siguiente paso

Un paso grande esconde errores porque nadie lo revisa hasta que corregirlo ya resulta costoso.

El tamaño del paso es una decisión08 / 31

En la vista web: agrupar por Etapa13 / 31

Crear el tablero

★

El proyecto y el campo Etapa se crean por separado para obtener cuatro estados reales

gh project create --owner @me --title "Curso OpenClaw+Codex" --format json
gh project field-create <numero> --owner @me --name Etapa \
  --data-type SINGLE_SELECT --single-select-options "Por hacer,Haciendo,Revisión,Hecho" --format json

El proyecto nuevo solo trae Todo, In Progress y Done; el segundo comando define las etapas del curso.

Fuente: GitHub CLI · gh project field-create14 / 31

Agregar la tarjeta

★

La especificación entra al tablero como tarjeta, no como una copia del texto

gh project item-add <numero-proyecto> --owner @me \
  --url https://github.com/TU_USUARIO/mi-agente-infra/issues/N --format json

La salida devuelve el ITEM_ID. La tarjeta enlaza la issue; el campo Etapa vive en el proyecto.

Bloque 3 de 420 / 31

El ciclo de una tarea

Cada paso se ejecuta, se compara contra el criterio y deja evidencia antes del siguiente

paso pequeño→comparar con el criterio→dejar evidencia→solo entonces, el siguiente paso

Ninguna parte del ciclo se salta: sin evidencia comentada, el siguiente paso no empieza.

El mismo ciclo para cualquier tarea futura21 / 31

Qué cuenta como evidencia

«Ya lo hice» no es evidencia; un antes/después comparable sí lo es

Evidencia real

  • Un diff del archivo cambiado
  • Una respuesta comparada antes y después
  • Un comando y la salida exacta que devolvió

No es evidencia

  • «Ya quedó»
  • «Lo probé y funciona»
  • Una captura sin fecha ni contexto

Rastro verificable, paso a paso23 / 31

Los cuatro frenos

Cuatro señales detienen al agente antes de seguir, aunque el pedido suene simple

1Irreversiblecerrar, publicar o borrar
2Sensiblecredenciales o datos personales
3Fuera de alcanceotro repo o issue
4Especificación rotacriterio poco claro

Ante cualquiera de los cuatro, el agente muestra el motivo y espera; no improvisa un criterio propio.

Frenos, no excepciones24 / 31

Contrato de delegación

El agente ejecuta y deja evidencia; la persona revisa antes de autorizar el siguiente paso

Agente
  • ejecuta el paso
  • compara con el criterio
  • comenta evidencia
  • se detiene ante un freno
ESPERA
Persona
  • lee la evidencia
  • decide si alcanza
  • autoriza el siguiente paso
  • autoriza mover a Revisión

Revisión final

La especificación se relee completa antes de decidir si el criterio ya se cumple

Antes

Objetivo, alcance y criterio escritos al inicio del bloque 1.

Después

Los comentarios de evidencia acumulados durante el bloque 3.

Si alguna parte del criterio no tiene evidencia, la tarea sigue en Revisión, no en Hecho.

Comparar, no suponer28 / 31

Cierre

★

La tarjeta pasa a Hecho y la issue se cierra citando la evidencia, no solo «listo»

gh issue close N --reason completed \
  --comment "Criterio de aceptación cumplido: <evidencia final>"
