Sesión 4 · Apéndice práctico

Conectar herramientas sin perder el control

Mapa sencillo de MCP, APIs, CLI, OAuth, autenticación y tokens; más los comandos Git/GitHub explicados para pedírselos a OpenClaw.

1 · Mapa mental

Seis formas de conectar una herramienta

MCP

Un enchufe estándar para que el agente use herramientas y recursos, como archivos o una base de datos.

API REST

Una dirección web que recibe una solicitud y devuelve datos, como el estado de un deployment.

CLI

Un programa manejado por órdenes, como gh repo view.

OAuth

Permiso delegado en una web, sin entregar tu contraseña al agente. Ejemplo: Gmail o GitHub.

Auth

Comprueba quién eres y qué puedes hacer; puede usar sesión web, OAuth o una clave.

Token / API key

Credencial de acceso que se guarda como secreto y nunca se pega en el chat o Git.

Pregunta siempre: ¿qué permiso necesita, dónde se guarda y cómo se revoca?

3 · Patrón seguro

Antes de conectar, pregunta cuatro cosas

  1. ¿Qué alcance tocará?
  2. ¿Será solo lectura, edición o publicación?
  3. ¿Dónde vive el secreto y cómo se revoca?
  4. ¿Qué evidencia devolverá?
«Trabaja solo en [alcance]. Explica el conector y el permiso. No muestres credenciales. Haz primero una comprobación de solo lectura y detente antes de enviar, publicar, borrar o gastar créditos».

4 · Git y GitHub

Comandos: qué son y cómo pedírselos a OpenClaw

ComandoQué hacePedido sencillo
git initConvierte una carpeta normal en repo local.«Inicializa Git solo aquí».
git statusMuestra cambios y archivos nuevos.«Dime qué cambió, sin modificar».
git addElige archivos para el commit.«Prepara solo estos archivos».
git diff --cachedRevisa la propuesta antes de guardarla.«Enséñame diff y busca secretos».
git commitRegistra una decisión con nombre.«Propón mensaje y espera aprobación».
git log / git showLee historial o un commit.«Resume decisiones» / «Muéstrame este hash».
git branch / git switchCrea o cambia una línea de trabajo.«Crea una rama para esta tarea».
git mergeIntegra una rama en otra.«Propón la integración; no mezcles aún».
git restoreRecupera un archivo.«Restaura solo este archivo de prueba».
git remote -vMuestra el remoto configurado.«Dime a qué URL apunta».
git pushCopia commits al remoto.«Publica el commit aprobado y devuelve URL, rama y hash».
git pullTrae cambios del remoto.«Revisa qué llegaría; no integres aún».
gh auth login/statusConecta y comprueba GitHub.«Abre login web y verifica sin tokens».
gh repo create/clone/viewCrea, reconstruye o consulta un repo.«Crea privado» / «clona y compara hashes» / «verifica URL y privacidad».
gh issue create / gh pr createAbre tarea o propuesta.«Redacta y enséñame antes de crear».
Control humano: autoriza tú antes de commit, push, merge, correo, deployment o gasto.

5 · Práctica S04

Conectar una herramienta en cuatro movimientos

  1. Nombrar objetivo.
  2. Elegir conector y permiso.
  3. Probar en modo lectura y pedir evidencia.
  4. Autorizar el efecto externo después de revisar.
Actividad: elige GitHub, Gmail, Vercel, Railway o una API de LLM y documenta objetivo, conector, permiso, secreto, pedido y evidencia.
